---
name: 协作工作方式与汇报口径
type: 用户偏好
description: 多 Agent 协作：先建任务/提计划待批，收口汇报固定口径，启动队友前需用户确认。
---

在本项目（Harness-Agent 多 Agent 协作）中，用户/协调方期望：1. 涉及改/新增功能应先建任务、提议团队并等待用户批准后再动手；分析与审查类请求可直接进行。2. 队友 Agent 通过 submit_plan 提交计划，需经审批后方可执行；空闲时用 idle_report 汇报；审批结果需通过消息总线通知对应 Agent 才算放行。3. 完成工作区侦察、任务板创建与依赖建立，并向用户给出团队分工提议后，必须等待用户明确确认，之后才启动（spawn）并行队友执行各任务，不要跳过确认。4. 任务收口汇报必须包含：文件清单、pytest 用例数与结果、受保护文件的 sha256 比对、worktree 干净度、分支提交哈希。5. 分解子任务需用 todo_write 维护阶段进度，长时间不更新会被系统提示。
