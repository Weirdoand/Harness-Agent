# MCP需求文档

## 背景与目标

当前 Agent 通过工具描述列表向模型声明可调用的工具，并通过处理函数映射执行对应调用。引入 MCP 后，工具来源不再只有程序内预先定义的常规工具，还包括运行期间连接的 MCP 工具。因此，需要使用统一的工具池管理两类工具，使 `agent_loop` 始终能够获得当前有效的工具描述，并将工具调用分发到正确的处理函数。

本需求的目标如下：

- 统一管理常规工具和已经连接的 MCP 工具。
- 保持工具描述与处理函数映射相互对应。
- 支持在运行期间通过 `connect_mcp` 连接指定 MCP，并将其工具加入工具池。
- 在每次 `agent_loop` 开始时刷新工具池，使新连接的 MCP 工具能够参与后续模型调用。

本文描述目标结构和预期行为，不表示相关 MCP 能力已经完成实现。

## 术语说明

| 术语 | 说明 |
| :--- | :--- |
| `TOOLS` | 提供给模型的常规工具描述列表。每项描述应包含工具名称、用途和参数等信息。 |
| `HANDLER(FUNCTION)` / `FUNCTIONS` | 常规工具的处理函数映射，根据工具名称找到并执行对应函数。`HANDLER(FUNCTION)` 是本需求中的概念称呼，`FUNCTIONS` 是当前项目使用的对应结构。 |
| 工具池 | 统一汇总工具描述和处理函数映射的运行时结构，数据来源包括常规工具和已经连接的 MCP 工具。 |
| `MCPClient` | 描述并管理一个 MCP 的客户端结构，负责记录该 MCP 暴露的工具并完成注册和调用。 |
| `MCP_SERVERS` | 可连接 MCP 的服务注册表。`connect_mcp` 通过 MCP 名称在其中查找对应服务。 |
| `MOCK_SERVERS` | 本地开发或测试时使用的模拟服务注册表，用于在没有真实 MCP 服务时替代 MCP。 |
| 工具描述 | 提供给模型的工具元数据，用于说明工具名称、功能和调用参数。 |
| 函数映射 | 工具名称与可执行处理函数之间的对应关系，用于执行模型产生的工具调用。 |

> 说明：本文没有确定的参数类型、返回对象格式和具体容器类型均属于实现建议，不作为对现有规则的替换。

## 工具池
- 将原先的工具调用改成工具池进行处理
- 内部处理 tools 和 handler

1. 先将常规的 TOOLS 和 HANDLER(FUNCTION) 记录
2. 再将 MCPClient 中的 mcp 工具进行记录

### 工具池职责

工具池需要同时维护以下两类信息：

1. **工具描述集合**：提供给模型，用于选择和生成工具调用。
2. **处理函数映射**：供调用分发层使用，根据工具名称执行相应的常规函数或 MCP 映射函数。

工具池的构建顺序保持为：

1. 读取并记录常规 `TOOLS`。
2. 读取并记录常规 `HANDLER(FUNCTION)`；在当前项目中，对应结构为 `FUNCTIONS`。
3. 遍历已经连接的 `MCPClient`。
4. 将各 `MCPClient` 的工具描述加入工具描述集合。
5. 将各 `MCPClient` 的映射函数加入处理函数映射。

工具池刷新时应从上述数据源重新汇总当前有效内容，避免因为多次刷新而重复追加同一工具。常规工具应始终可用；MCP 工具只在对应 MCP 已经成功连接并完成注册后加入工具池。

### 描述与处理函数的对应关系

- 每个可调用工具都应同时存在工具描述和对应处理函数。
- 工具名称是工具描述与处理函数映射之间的关联标识。
- 如果只有工具描述而没有处理函数，该工具不能进入可调用状态。
- 如果只有处理函数而没有工具描述，该函数不应作为工具暴露给模型。

## MCP结构
- 通过 MCPClient 的结构进行描述一个 mcp 的工具
- 内部含有两个函数(注册, 调用), 三个变量(mcp名字, 工具描述列表, 映射的函数列表)

1. 工具描述列表中需要写入对应函数的描述信息

### `MCPClient` 职责

每个 `MCPClient` 实例对应一个 MCP，负责隔离该 MCP 的名称、工具描述、函数映射和调用过程。

#### 三个变量

| 变量 | 职责 |
| :--- | :--- |
| MCP 名字 | 标识当前客户端对应的 MCP，并用于连接状态识别和问题定位。 |
| 工具描述列表 | 保存该 MCP 对外提供的全部工具描述，供工具池合并到模型可见的工具列表。 |
| 映射的函数列表 | 保存该 MCP 工具名称与实际调用函数之间的对应关系，供工具池合并到处理函数映射。 |

#### 两个函数

1. **注册函数**
   - 从对应 MCP 服务读取或接收工具信息。
   - 将每个工具的描述写入工具描述列表。
   - 为每个工具建立对应的调用函数映射。
   - 只有工具描述和映射函数均准备完成时，该工具才视为注册完成。
2. **调用函数**
   - 接收工具名称和调用参数。
   - 从映射的函数列表中查找对应函数。
   - 执行调用并返回结果；调用失败时返回或抛出可定位到 MCP 名称和工具名称的错误信息。

上述变量的具体字段名、列表或字典形式，以及两个函数的参数签名，属于实现阶段确定的内容；实现结果必须满足本文规定的职责和对应关系。

## 例子
本地使用这两个代替MCP
```
MOCK_SERVERS = {
    "docs": _mock_server_docs,
    "deploy": _mock_server_deploy,
}
```

### 本地模拟说明

`MOCK_SERVERS` 用于本地开发和测试。示例中的 `docs`、`deploy` 是可连接的模拟 MCP 名称，对应值是提供模拟工具信息和调用能力的本地函数。

本地模拟流程与真实 MCP 的目标行为保持一致：

1. 使用 MCP 名称查找对应的模拟服务。
2. 通过 `MCPClient` 注册模拟服务提供的工具描述和映射函数。
3. 刷新工具池。
4. 由模型选择工具，再通过工具池中的处理函数映射完成调用。

该示例只说明本地替代关系，不限定真实 `MCP_SERVERS` 的连接协议或传输方式。

## 流程说明
- 每次 agent_loop 开始的时候会更新一遍工具池

### `agent_loop` 开始时的刷新流程

1. 创建本轮使用的工具描述集合和处理函数映射。
2. 按顺序写入常规 `TOOLS` 和 `HANDLER(FUNCTION)`。
3. 读取当前已经连接且注册成功的 `MCPClient`。
4. 写入各 MCP 的工具描述和映射函数。
5. 对工具名称及描述与函数的对应关系进行检查。
6. 将刷新后的工具描述集合提供给模型，将处理函数映射提供给工具调用分发层。

每次刷新应以当前数据源为准重新构建或进行等价的去重更新，保证同一个 MCP 或工具不会因为多次进入 `agent_loop` 而被重复注册。若某个 MCP 在上一轮之后连接成功，其工具应在下一次 `agent_loop` 开始刷新后可用。

### 完整调用流程

```mermaid
flowchart TD
    A[agent_loop 开始] --> B[记录常规 TOOLS]
    B --> C[记录常规 HANDLER / FUNCTIONS]
    C --> D[读取已连接的 MCPClient]
    D --> E[合并 MCP 工具描述和函数映射]
    E --> F[校验并完成工具池刷新]
    F --> G[模型选择并发起工具调用]
    G --> H{工具来源}
    H -->|常规工具| I[调用常规处理函数]
    H -->|MCP 工具| J[调用 MCP 映射函数]
    I --> K[返回工具结果]
    J --> K
```

## 新增工具
- 新增 connect_mcp 用于添加 mcp 的工具, 内部会判断 MCP_SERVERS 中是否存在指定 mcp

### `connect_mcp` 职责与流程

`connect_mcp` 接收要连接的 MCP 名称，并按以下流程处理：

1. 检查 `MCP_SERVERS` 中是否存在指定 MCP。
2. 如果不存在，结束连接流程并返回明确的“服务不存在”结果。
3. 如果存在，获取对应 MCP 服务并创建或取得相应的 `MCPClient`。
4. 调用 `MCPClient` 的注册函数，记录工具描述列表和映射的函数列表。
5. 注册成功后记录该 MCP 为已连接状态。
6. 更新工具池，或确保其在下一次 `agent_loop` 开始时被工具池刷新流程读取。
7. 返回包含 MCP 名称和连接结果的明确信息。

`connect_mcp` 的参数类型、返回对象结构和同步或异步形式属于实现建议。无论采用何种形式，调用结果都应能够明确区分成功、服务不存在、注册失败和已经连接等情况。

### 重复连接

当指定 MCP 已经连接且注册完成时，不应重复添加相同的工具描述和函数映射。实现可以直接返回“已经连接”，也可以执行一次幂等刷新；无论采用哪种方式，工具池中都只能保留一份有效映射。

## 异常与边界情况

| 场景 | 预期行为 |
| :--- | :--- |
| 指定 MCP 不存在 | `connect_mcp` 返回明确的服务不存在结果，不修改当前工具池。 |
| MCP 连接失败 | 返回可定位到 MCP 名称的失败信息；未完成注册的工具不加入工具池。 |
| 工具注册失败 | 不将未完整注册的工具暴露给模型，并保留原有常规工具和其他已连接 MCP 工具。 |
| 工具描述缺失 | 该工具不进入可调用状态，并返回或记录缺失工具描述的信息。 |
| 映射函数缺失 | 该工具不进入可调用状态，并返回或记录缺失映射函数的信息。 |
| 重复连接 | 不重复添加工具描述或函数映射，保持连接操作幂等。 |
| 工具名称无法映射 | 不执行未知工具，并返回明确的工具不存在或无法映射信息。 |
| MCP 工具调用失败 | 返回或抛出包含 MCP 名称、工具名称和失败原因的错误信息，不影响其他工具继续使用。 |
| 工具池刷新失败 | 保留可用的常规工具和此前有效的工具状态，输出可定位刷新阶段的错误信息。 |

错误信息的具体数据格式由实现阶段确定，但不得只返回无法定位问题来源的空结果。

## 验收标准

1. 工具调用入口已经由统一工具池提供工具描述和处理函数映射。
2. 工具池构建时先记录常规 `TOOLS` 和 `HANDLER(FUNCTION)`，再记录已经连接的 `MCPClient` 工具。
3. 每个 `MCPClient` 均能表达一个 MCP，并具备注册、调用两个职责，以及 MCP 名字、工具描述列表、映射函数列表三类数据。
4. MCP 工具描述列表中的每个工具均包含对应函数的描述信息。
5. 本地环境可以使用文档中的 `MOCK_SERVERS` 代替真实 MCP 完成注册与调用流程。
6. 每次 `agent_loop` 开始时都会刷新工具池，新连接的 MCP 工具能够在刷新后提供给模型。
7. `connect_mcp` 会先检查 `MCP_SERVERS` 中是否存在指定 MCP，只有存在且注册成功后才添加其工具。
8. 工具描述和处理函数保持一一对应；任何一项缺失时，该工具不会进入可调用状态。
9. 多次连接同一 MCP 或多次刷新工具池不会产生重复的工具描述和函数映射。
10. 服务不存在、连接失败、注册失败和调用失败均有明确且可定位的结果。
11. 新增 MCP 能力不会导致已有常规工具从工具池中丢失或无法调用。

## 实现边界

- 本文不限定 MCP 的具体通信协议、传输方式或第三方 SDK。
- 本文不限定工具池、工具描述列表和函数映射使用列表、字典或自定义类实现。
- 本文不限定错误结果使用异常、状态对象或字符串返回。
- 上述未限定事项可由实现阶段选择，但不得改变本文保留的已有规则、执行顺序和职责关系。
