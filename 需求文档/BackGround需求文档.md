# Background 任务处理需求文档

## 1. 背景与目标
在当前的 Agent 运行机制中，部分工具（如 `bash` 命令）的执行可能会耗费较长时间。如果同步阻塞等待这些工具完成，会导致 Agent 响应缓慢，甚至影响整体任务流程的推进。
因此，需要引入后台任务（Background Task）处理机制，允许特定工具在后台异步执行，Agent 可以继续其思维与执行循环，并在后续轮次中获取后台任务的结果。

## 2. 核心架构设计

### 2.1 新增 `BackgroundManager` 类
负责统一管理所有后台运行的工具任务。
- **状态记录**: 记录所有后台任务（bg）的当前状态（如 `RUNNING`, `COMPLETED`, `FAILED`, `TIMEOUT`）。
- **结果存储**: 记录所有已完成 bg 的执行结果（标准输出、标准错误、退出码）。
- **生命周期管理**: 提供任务提交、状态查询、结果获取、任务终止等接口。
- **唯一标识**: 每个任务分配全局唯一的 `bg_id`（如 UUID）。

### 2.2 支持的工具
- 当前首批支持：`bash` 工具。
- 未来可扩展：其他耗时工具（如网络下载、长时间的数据爬取、大文件处理等）。

## 3. 处理逻辑与数据流

### 3.1 任务触发与占位符替换
1. **触发时机**: 在工具执行调度层，如果检测到使用的是 `bash` 且被标记为需要后台执行（或默认开启），则将其拦截，交由 `BackgroundManager` 异步执行。
2. **占位符生成**: 任务提交后，工具执行结果不会立即返回实际输出，而是返回一个带有 `bg_id` 的占位符（例如：`[Background Task {bg_id} Started]`）。该占位符会被记录在 Agent 的 `messages` 历史中。

### 3.2 任务后台执行
1. **线程隔离**: 内部通过单独开启一个线程（或协程/进程池）执行对应的工具函数。
2. **安全隔离**: 确保多线程环境下的数据安全，执行过程中捕获所有的异常与超时情况。

### 3.3 结果轮询与回填
1. **状态更新**: 后台任务执行完毕后，更新 `BackgroundManager` 中的状态和结果缓存。
2. **周期检查**: 在 Agent 每次工具循环的开始阶段（或每次向大模型发请求前），检查所有未完成的 `bg_id`。
3. **数据填充 (background_result)**: 如果某个 `bg_id` 对应的任务已完成，获取其 `background_result`。将该结果注入到上下文中（根据 `bg_id` 替换原始的占位符位置，或作为新的通知信息追加）。

## 4. 边界情况与异常处理
1. **超时处理**: 需要为后台 bash 任务设置合理的超时时间，超时后自动 Kill 进程。
2. **日志截断**: 如果 bash 输出大量日志，需进行合理截断（如保留前 1000 行和最后 1000 行），防止上下文超限，避免撑爆 Token。
3. **任务干预**: 允许 Agent 主动调用特殊工具（如 `manage_task`）来查询或终止正在运行的 `bg_id`。
4. **并发限制**: 限制最大并发后台任务数（例如 5-10 个），避免耗尽系统资源。
