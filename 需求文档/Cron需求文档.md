# Cron 定时任务需求文档

## 概述
用于赋予 LLM 处理和规划定时任务的能力。通过该模块，LLM 可以主动设定在未来某个时间点或按照特定周期执行特定的 `prompt` 任务，实现如定时提醒、周期性巡检、延时任务等自动化能力。

## 规则
用于提供在开发和使用定时任务功能时的规范与限制。
- **统一管理**: 必须通过一个全局的 `CronManager` 模块来进行统一定时任务的管理、调度以及对外提供工具接口。

### 时间表示
- 统一使用 **Cron 表达式** 来进行表达时间。
- 需要支持标准的 Cron 格式（如 5 位或 6 位 Cron 表达式）。
- 需明确约定时区（建议默认使用系统本地时区）。

---

## 交互设计：新增 LLM 工具
为了让 LLM 能够操作定时任务，需要通过 `CronManager` 向上层暴露以下三个工具（Tool）：

### 1. 创建定时任务 (Create_Cron_Job)
- **描述**: 允许 LLM 提交一个新的定时执行计划。
- **输入参数**:
  - `cron_expression` (String): 必填，Cron 表达式（例如 `0 8 * * *` 每天早八点）。
  - `prompt` (String): 必填，任务触发时发送给 LLM 执行的指令文本。
  - `is_recurring` (Boolean): 选填，是否循环执行。若为 false，则触发一次后自动销毁；若为 true，则按 Cron 周期不断触发。
  - `is_persistent` (Boolean): 选填，是否持久化。
- **返回结果**: 创建成功后返回唯一的 `job_id`。

### 2. 取消定时任务 (Cancel_Cron_Job)
- **描述**: 允许 LLM 提前终止一个尚未触发或正在循环的定时任务。
- **输入参数**:
  - `job_id` (String): 必填，需要取消的任务 ID。
- **返回结果**: 返回取消成功或失败（如找不到对应 ID）的状态。

### 3. 获取定时任务列表 (Get_Cron_Jobs)
- **描述**: 允许 LLM 查询当前系统中所有活跃的定时任务，以便进行自我检查和管理。
- **输入参数**: 无。
- **返回结果**: 返回当前任务列表，包含每个任务的 `job_id`、`cron_expression`、`prompt` 以及预计的下次触发时间。

## 架构设计：CronManager 与双线程监听模型
整个 Cron 系统由 `CronManager` 实例进行生命周期管理。为了不阻塞主程序的 `agent_loop`，`CronManager` 内部需要维护两个独立的后台线程来进行任务监听与分发：

### 线程一：时间轮询与调度线程 (Scheduler Thread)
- **职责**: 负责处理当前时间，判断是否已经有可触发的定时任务。
- **工作流**:
  1. 周期性唤醒（如每秒），遍历 `CronManager` 内存中维护的所有活跃 `CronJob`。
  2. 对比当前时间与 Cron 表达式解析出的下次触发时间。
  3. 如果时间已到，且当前时间戳与该任务的 `上次触发时间` 存在足够间隔（避免同一分钟内重复触发），则触发该任务。
  4. 将触发的任务标记为 `是否有待交付的触发任务 = true`，并将其加入到“待执行定时任务队列”中。

### 线程二：任务执行与分发线程 (Executor Thread)
- **职责**: 负责消费“待执行定时任务队列”，将任务实际交由 LLM 执行。
- **工作流**:
  1. 监听读取“待执行定时任务队列”。
  2. 当有任务到来时，提取任务的 `prompt`。
  3. 新启动（或调用）一个新的 `agent_loop` 实例，将 `prompt` 注入并开始执行对话。
  4. 投递成功后，将该任务的 `是否有待交付的触发任务` 状态恢复为 false。
  5. 如果任务的 `is_recurring` 为 false，则从内存和持久化存储中清理该任务。

## 数据模型：定时任务描述信息 (CronJob)
通过 `CronJob` 类/结构体来表示一个定时任务的完整描述信息。`CronManager` 内存中维护的定时任务总数**最多不超过 100 个**。

需要包含以下核心字段：

| 字段名 | 类型 | 说明 |
| :--- | :--- | :--- |
| `job_id` | String | 唯一标识符（如 UUID）。 |
| `cron_expression` | String | 触发时间，使用 Cron 表达式存储。 |
| `prompt` | String | 任务触发时，实际需要 Agent 去执行的指令。 |
| `is_recurring` | Boolean | **是否循环执行**。True 表示周期任务，False 表示一次性任务（如延时执行）。 |
| `is_persistent` | Boolean | **是否持久化**。如果为 True，则会将该任务数据序列化保存到本地硬盘；`CronManager` 启动时负责加载并恢复状态。 |
| `has_pending_task` | Boolean | **是否有待交付的触发任务**。状态位，表示时间已到并进入队列，但还没发送给 LLM（防止重复调度）。 |
| `last_trigger_time` | DateTime | **上次触发时间**。用于防抖，避免在一分钟内同一个 Cron 表达式被重复触发多次。 |
